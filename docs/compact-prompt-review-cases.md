# 紧凑交付复核案例

这些是宿主行为验收任务，不是已运行的图像实验。程序回归中的语义判断是合成声明，不证明宿主能正确消歧、去重或提高成图效果。

## 1. 已有提示词保持粒度

输入：写实风格，一位成年古风女子，精致五官，红瞳柔唇，乌黑长发配流苏发簪，浅米色透纱高开叉长裙，手臂金纹，双臂舒展、迎面缓步走来，中式庭院青石板路、古树院墙，黄昏暖金逆光，低角度仰拍，景深虚化。请求：保留原设计，整理得紧凑一些。

检查：逐项保留输入，按已有提示词整理而非重开三套创意；精致五官保持原粒度，不自行指定鹅蛋脸、眼皮、鼻型；不自动增加半束发结构、胸下裙腰、湿石板等。红瞳若存在实质歧义应明确处理而不是叠加深棕眼睛。已有母版的修改与确认沿用原流程。

## 2. 重叠内容与不同限定

母版分别记录：沿石板路迎面缓步走来；庭院青石板路；双臂自然舒展；一侧高开叉裙装。允许组合为一两句，重复动作表达一次；舒展动作和开叉限定都保留。一个准确正文引文可在多个设计项的复核中引用。

同一裙装的“浅米色”“半透明”“纱质”是独立限定，不能只留“长裙”。两个不同人物的烟熏妆分别明确归属，不能把它们错误合成只有一人化妆。用户明确要求重复或强调时按其意图执行。

## 3. 理由与可见结果

母版意图为“人物第一、逆光第二、庭院第三”，已选可见事实为人物居中、轮廓逆光、背景虚化。正文保留可见事实，层级编号留在内部；“避免剪影”若已落实为柔和前补光，则表达补光，不再附带重复的效果保证。不能删除已经确认的实际补光。

## 4. 独立细节与新创作

用户明确指定鹅蛋脸、内双杏眼、半束发、胸下束腰或石板潮湿时，紧凑整理仍保留这些要求。用户请求重新设计造型时恢复完整创意流程，主动解决关系问题，允许增加有用途的细节。

## 5. 名称、跨语言与路由

烟熏妆、低马尾等已确认名称只需在实际对应描述中表达一次，允许既有映射中的等义别名；不替换为“妆容自然、发型整齐”。英文等义与not_checked仍按编译契约处理。Grok比例块外；Qwen仍按路由单段表达；Layout保留合法JSON和各对象必要字段，不把“紧凑”变成破坏结构的理由。

## 记录方式

保存原需求、实际母版、实际最终提示词、宿主及目标路由。列出遗漏、擅加、冲突、跨区域复述与解释性内容；字数只作为辅助数据，不以更短直接判为更好。真实图像效果另用同条件对照验证。
