# LLM Compiler 与最终检查

Compiler 是宿主 LLM，不是 Python 翻译器。仅从当前已展示且获用户版本确认的母版编译。
通用自然语言使用连贯描述；覆盖媒介、主体（包括人物可见的面部、妆容、发型与服装及其已确认名称）、瞬间、动作、空间、镜头、光色和可见材质，信息由画面需要决定，但已确认名称不因“画面需要”省略。
所有已确认可编译设计都应保留；只可等义合并重复表达。发现缺失设计退回总导演。
母版已确认的妆容、发型名称必须写进正文：原样，或目标语言中的等义常用名称；“妆容自然”“面部干净”“发型整齐”这类泛称不算覆盖。只有母版本身未选定名称，或本景别确实不可见且已在交付时明确告知用户，才可不写名称；必要限定只在母版已选定后才补充。名称可以独立交付，不强制展开成化妆/理发步骤，也不把“学生妆”“舞女妆”等职业标签当妆容术语。广义或地域风格依母版给少量实际特征，不把泛称当精确、统一标准。无妆不译为裸妆。跨语言使用语义相符的常用名称，目标模型规则仍按原路由必读。
历史发式可用常用古称；生僻古称需要区分形态时补本图已选的轮廓、位置或固定关系。朝代/身份关联是设计依据，不整段译为成品；不擅加冠帽或把架饰译成真发。名称+特征不保证优于名称本身。不得为了“更专业”擅加眼线、修容、腮红、颊色、高光、肤色、发色、汗水或脱妆；不得为了精简丢弃已确认鼻型、眉形、妆色、妆容名称、发型名称、服装名称等要求。程序只能检查覆盖、名称与引文证据；术语被模型识别和成图自然度均需真实图像证据。

## 名称与引文证据（程序可核对）

1. 名称不是检索关键词。程序按 [names.json](../knowledge/names.json) 的名称组核对：每组只含一个设计名称与明确登记的等义表达；标题斜杠两侧的不同形态不会被自动当成同义别名。
2. 人物美术区每个 visual_fact 按映射检查三项之一：名称或登记别名出现在该项对应段落（Layout 为人物/物件 caption）记 `matched`；目标语言有对应表达但未出现记 `missing`；映射未覆盖或缺少目标语言别名记 `not_checked`。
3. 候选可用可选 `language` 字段声明正文语言：接受常见 BCP-47 风格标记（如 `zh-CN`、`en`、`ja-JP`）；空值、数字、含空格或非拉丁标签等无效值直接拒绝。自动名称别名检查只覆盖 `zh` 与 `en`；其他合法语言不被静默当成中文或英文，相关名称组一律 `not_checked` 并沿用复核证据。省略 `language` 时按路由默认语言判断。语言属于复核绑定，改变后旧复核失效。
4. `missing` 阻止提交与交付。`not_checked` 不伪装成 matched：编译报告与交付结果必须列出该设计项及原因；复核 note 必须写出母版原名称或原描述（短值可整体引用；较长事实优先引用待复核的原名称，不能拿无关的任意四字充数），并给出覆盖该项的准确正文引文「…」。正文对应表达短于4字时，只有它是已登记名称/别名或母版原文且按词边界命中才有效；较长引文须在对应段落中出现。等义性由宿主判断，程序只核对母版片段与引文归属；not_checked 不因复核 pass 改为 matched。
5. 引文必须取自覆盖该设计项的段落；不得拿其他段落或任意句子充数。
6. `matched` 只代表列出的名称组。程序中未识别的其他名称、正文化名与特征仍由逐项语义复核；名称出现本身不证明用在正确人物上、不是否定句，也不证明颜色、位置、形态或其他已确认要求被保留；裸妆与无妆不是等义。
7. Layout 只从实际描述字段（`summary.caption`、character/object 的 `caption`）取证；`meta`、`tags`、`palette` 和用于画面可读文字的 `text` 不作为人物妆发名称证据。
8. 名称检查范围包含人物美术区所有 visual_fact：无登记名称组的事实如实列入 `name_checks`（`not_checked`，并写明是否属名称类 facet）；不能因 facet 写法不同而让事实消失。映射未覆盖的名称不会被自动发现，报告只按列出的名称组声明覆盖。

工具manifest包含master_hash、facts、constraints、adapter_id及aspect_ratio_delivery（配置路由）。命令`manifest --target <已登记路由>`只选择表达方式，不选择或改变画幅。未指定目标仍可明确交付generic，不把未实现模型静默当generic。
本地submit和deliver要求当前版本已生成manifest，改版后须重新生成。manifest绑定版本、母版哈希和路由；没有Python时宿主按同样顺序记录当前目标与版本，但须说明未执行程序门禁。
候选格式：
- master_hash
- segments：每段 text、item_ids
- parameters：aspect_ratio 的 width/height
- target：已选路由名；省略仅为兼容既有generic候选，不代表自动识别模型
- language：可选正文语言（如 `zh-CN`、`en`）；省略时按路由默认语言判断名称别名覆盖，用户覆盖语言时必须填写

每个目标均须按[目标模型加载表](model-routes.md)读取对应专属全文，不因熟悉或简单而跳过；正文有效复用条件见该表。只有显式MOSS Layout候选在parameters中另提供image_size的width/height，作为已确定的实际画布尺寸；其他路由不接收该字段。Layout的一个segment承载完整模型JSON及其覆盖ID，不把九区域母版原样传给模型。尺寸和JSON均绑定成品哈希，修改后必须重新复核。没有可靠尺寸时不能编造Layout，核心自然语言创作仍可继续并明确未完成Layout交付。

段落可覆盖多项；覆盖 ID 只是声明，不证明真实等义。
segments不预写比例控制，由Adapter从parameters生成路由规定的块内比例行/参数或块外设置。参数在结构对象中保留是校验依据，不是要求对用户重复显示。未确认比例、比例与母版不同、路由不支持或语义uncertain均不得放行。

宿主对 Adapter 后的实际最终成品重新逐项检查：
omissions（遗漏）、additions（擅加）、relations（关系改变）、requirements（明确要求）。
另给每个可编译 ID 的 result 和可审查 note。结果 pass/fail/uncertain。
review绑定master_hash和artifact_hash，写reviewer与evidence_ref。显式target的哈希同时绑定路由配置和最终排版；改变目标或路由后必须重新复核，不能沿用旧pass。禁止在没有复核时批量填写pass。
Python 检查字段、哈希、版本、覆盖 ID、文字原文、比例和预算；无法证明语义。
最终任一必要项 fail 或 uncertain 不放行。失败最多自动修复一次；不可通过重新准备 manifest 重置预算。

文本宿主没有 Python 时仍按同一事实清单和语义合同检查；不能宣称程序强制或已永久保存。

## 服装术语与实际衣件

按已确认母版编译服装，不在编译阶段重新选衣。常用名称可直接表达；古称或多义名称补必要轮廓与层次，不抄服饰史说明。形制、纹样、用途分清，不能将晚清衬衣译成现代shirt、将披帛译成完整上衣、将飞鱼服当唯一版型或将马面裙简化成任意pleated skirt。翻译不足以区分时用名称加简短结构；有明确结构就覆盖结构。变体择已选项，不自动添加全套冠带、徽章、露肤或现代品牌文字。删改已确认衣件仍返回母版修改流程。
